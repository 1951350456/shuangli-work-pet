# 显示大小与动作显示异常

## 小尺寸与颗粒感

Pets v2 的单格固定为 192 × 208 像素。上传更大的整张图片会违反格式，不能提升每一帧的分辨率。Q 版通过放大头部、五官和轮廓，减少衣服上的细碎纹样，改善小尺寸下的辨识度。

实际大小在「设置 → Pets → Customize → Pet size」调整，见 [Pets 官方说明](https://learn.chatgpt.com/docs/pets)。预览页的显示宽度滑杆用于观察不同大小；默认使用像素化缩放，与本次检查的客户端一致。“平滑参考”只改变网页预览。

## 拖动、挥手、跳跃时下半身透明消失

用户报告这一现象主要出现在拖动、挥手、跳跃期间，并进一步澄清：实际是下半身变透明、只剩上半身，而非白色矩形盖住角色。裁切范围或动作显示区域异常是待验证的假设，尚未确认根因。对当时从 Pets 下载的旧版成品重新检查，结果如下：

- 1536 × 2288、v2 格式，全部 73 个必要帧存在，15 个未用单元透明。
- 帧数为 `[6,8,8,4,5,8,6,6,6,8,8]`，与检查时客户端使用的帧数相同。
- 全部必要帧的下半部分都有角色像素，未发现空白帧、整块不透明背景或透明像素中的残留 RGB。
- 本地结构检查和 Pets 服务端预检均通过。

这些结果排除了部分素材问题，**不能证明客户端的实际播放正常，也不能证明 Q 版重绘能修复运行时故障**。消失、变白的根因尚未复现和确认。

网页预览提供“连续切换动作”，会交替播放动作和待机。可以在浅色、深色、透明网格背景下检查是否出现同样现象。若网页一直正常而 Pets 仍出现问题，请记录出现时的动作、显示大小、是否正在拖动、是否跨屏，以及异常画面。截图应只保留宠物区域，避免包含私人窗口。

## 已核对的加载路径

用户进一步观察到：自带宠物在设置中立即显示，而霜璃首次先透明、等待后才出现。检查时客户端的自带宠物引用程序内打包的图片，账号云端宠物引用远端图片 URL；这与首次下载/解码延迟相符。

所有 73 个动作帧共用一张 PNG。切换动作只改变同一张图的背景位置，不分别下载挥手、跳跃等动作。代码中约每五分钟刷新云端目录和图片记录，不等于每五分钟清空图片缓存。一次新签名图片地址的 HEAD 响应未给出 Cache-Control/Expires；这也不能单独证明浏览器完全不缓存。

现在可以使用 [本地安装器](local-install.md) 安装原生文件对，客户端的本地读取器会把图片文件读入内嵌图像。账号内随后出现了对应云端记录，但记录存在不能单独证明当前渲染图片的来源。

## 最新复测与默认 Codex 对比

2026-10-20，用户最初反馈本地版短时间正常，随后确认仍会加载失败。故障未修复，不能以短时间未复现宣称改善已稳定。

本机再次核对结果（客户端 26.1013.40934 / 20770）：

- 原生目录是 `CODEX_HOME/pets/<name>/`，默认 `~/.codex/pets/shuangli-local/`，其中清单和 PNG 都存在，校验和正确。`/pet` 是显示/隐藏桌宠的命令，不是部署目录。
- Pets 账号状态读回显示，当前选中的「霜璃（本地版）」已是 `pet_` 开头的云端 ID，而非 `custom:shuangli-local`。客户端将前者路由到云端图片，后者才读本地文件为内嵌图像。本地名称不能保证本地加载。
- 默认 Codex 图片随应用打包，文件名为 `codex-spritesheet-v6-51045ae208c0.webp`；不需要取得自定义宠物的云端签名图片链接。
- 两者图集均为 1536 × 2288、v2，且共用动画显示组件。Codex 打包图为 1,309,110 字节，霜璃本地 PNG 为 3,824,817 字节；解码成 RGBA 均占 14,057,472 字节，文件体积差异不能单独证明故障原因。
- 云端元数据刷新时，`O8s` 在已有指纹且图片路径相同时直接返回更新后的签名 URL，跳过新图片的 `decode()` 等待。显示组件 `E6s` 把 URL 直接赋给背景图，没有等待新图成功再保留/切换旧图的处理。这是一条与等待显示相符的代码风险，尚未通过故障当时的网络或渲染跟踪确认为根因。
- 现有日志没有可用于定位本次故障的宠物图片加载/解码错误；其他网络连接错误不能代替图片故障证据。

安装器不能修改客户端的自动云迁移、云端图片切换或缓存逻辑。当前保留安装工具和素材，但明确不承诺解决宿主加载故障。尚未获得能把这只自定义宠物固定为与内置 Codex 相同加载路径的受支持选项。

本仓库包含角色素材、网页预览和本地文件安装器；Pets 客户端的窗口合成、迁移策略和动画执行由宿主负责。
